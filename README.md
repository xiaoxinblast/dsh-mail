# DSH Mail

在 DeepSeek Harness 中阅读和整理邮件、管理日历与待办，并让邮箱助手通过同一套业务接口查找邮件、准备回复和提取事项。

**当前为开发预览版。** 仓库中的自动化测试和本机 DSH 验收不等于真实网易账号互通验收。版本验收记录见 [docs/VALIDATION.md](docs/VALIDATION.md)。请先使用测试账号验证，再连接重要邮箱。

## 安装

环境：Windows，DeepSeek Harness **0.2.2-rc.1**（Node.js 24.9 或更新版本）。插件使用 DSH 自带 Node / SQLite，不另起常驻系统服务。

打开 DSH → 插件 → 添加插件 → 安装第三方插件，填入：

```text
github:xiaoxinblast/dsh-mail#main
```

安装后启用 DSH Mail，按管理器提示重新载入或重启 DSH。仓库已包含 `dist/client.js`，正常安装无需手动构建。点击左侧“自动化任务”下方的 **DSH Mail** 可直接打开完整工作台，无需先进入会话；对话起始页移除重复的邮件图标，会话顶部的快捷入口保留。右上方 **AI 助手** 在 DSH Mail 内打开原生对话侧栏，可直接围绕当前邮件连续提问和调用工具。新建会话也可选择 **DSH Mail 邮箱助手**，继续使用会话右侧工作台。

邮件右上角的 **全屏显示邮件** 会覆盖整个 DSH 工作区，包括宿主默认左侧栏，并保留系统标题栏；点击 **收回侧栏** 返回原来的侧栏宽度和位置。AI 助手标题栏也提供切换按钮。当前邮件、草稿、对话、滚动位置和输入光标随同一界面保留；没有其他菜单或对话框时可按 Escape 收回。切换使用 180 毫秒的短过渡，系统开启“减少动态效果”时直接切换。详情见 [工作区全屏](docs/workspace-fullscreen.md)。

`main` 为安装来源；正式版本另外使用 `vX.Y.Z` 标签固定。不要使用版本豁免强行安装到未经测试的 DSH 版本。

## 连接网易 163

在工作台“设置 → 添加邮箱”填写完整邮箱地址、显示名称和**客户端授权码**。请在网易网页开启 IMAP/SMTP，并把客户端收信范围设为全部邮件。

| 连接 | 默认值 |
|---|---|
| IMAP | `imap.163.com:993`，隐式 TLS |
| SMTP | `smtp.163.com:465`，隐式 TLS |
| 用户名 | 完整邮箱地址 |
| 密码栏 | 客户端授权码，不能用网页登录密码代替 |

插件通过 ImapFlow 发送真实客户端 ID；`Unsafe Login` 会单独解释，不统一归为密码错误。凭据只在设置界面录入，使用 Windows 当前用户 DPAPI 加密，禁止通过 Agent 工具传入。备份不包含凭据，换机后需要重新连接。

支持多个账号，以及手动配置其他 IMAP/SMTP 服务。关闭“隐式 TLS”意味着强制 STARTTLS，不提供明文降级。同步后检查特殊文件夹映射，无法自动识别时，在账号设置选择已发送、废纸篓、垃圾邮件和归档文件夹。

## 工作台

- **邮件**：统一收件箱、账号/文件夹视图、离线缓存、分页与中日文全文检索、筛选和保存搜索、会话关联、原始邮件头、HTML/纯文本、回复/回复全部/转发、To/Cc/Bcc、富文本、内嵌图片、签名、模板和本地草稿。
- **整理**：服务器已读和星标、本地标签、延后处理、归档/移到废纸篓/垃圾邮件、恢复、确认后永久删除、批量操作、同账号与跨账号复制移动。
- **文件夹**：名称自然排序、邮件数量排序、即时查找、本机自定义颜色，以及新建、嵌套、重命名/移动、删除预览、复制结构及邮件；目标名称不可与现有文件夹冲突。复制任务保存逐封检查点，结果未知项目不会盲目重发。
- **附件和数据**：48px 图片内容缩略图、可折叠附件区域、Word/PDF/Excel/PowerPoint/压缩文件等类型卡片、图片/PDF 预览和下载；正文内嵌资源不计入附件数量或打包下载，明确作为附件发送的图片保留；EML/MBOX 导入导出；联系人 CSV/vCard 导入导出；不含凭据的数据备份恢复。
- **规则**：条件组合、优先级、动作顺序、样例预览、启停、历史应用预览和执行记录。后台规则只允许整理和本地待办，不允许自动发信、永久删除或对外邀请。
- **日历**：日/周/月/日程视图，多本地日历，全天、跨日、重复事件及单次例外，ICS 导入导出、邀请更新/取消、接受/暂定/拒绝回复草稿、提醒。
- **待办和联系人**：截止时间、优先级、完成状态、来源邮件；联系人分组与写信补全。

日历采用左侧小月历、日历勾选列表和铺满剩余区域的主网格。小月历支持切月、跳转日期，勾选可控制显示的日历；不足 1000px 时左栏改为抽屉。新建事件默认使用正常亮青色，可选择八种常用色、自定义颜色或“跟随日历颜色”。未结束事件保留正常色，按结束时间自动淡化；全天事件在显示时区的结束日期零点结束，结束日期不包含当天。显示会每 30 秒检查一次，已有日期和颜色记录不被改写。颜色保留在插件备份中，不写入对外 ICS 邀请。

工作台采用左侧图标导航，默认跟随 DSH 明暗主题。“设置 → 外观与动效”支持单独选择浅色或深色、六种强调色、密度、字号及关闭动效；外观预览可以取消。统一收件箱、已发送、星标、草稿和文件夹都从左侧图标进入；点击文件夹图标打开查找、排序和管理浮层，选择文件夹后自动收起。“已发送”聚合各账号配置的特殊文件夹；未配置时会提示前往“设置 → 邮箱账号 → 配置”，不会把全部邮件当作已发送。

账号下不重复列出收件箱，使用顶部“统一收件箱”查看；INBOX 本身不提供邮件角标颜色或标题彩色标签。收件箱中的邮件如果还位于项目文件夹，仍显示这些项目的颜色；只有没有任何非 INBOX 位置时才不显示角标。按 `\Inbox` 角色或大小写不敏感的完整路径 `INBOX` 识别，`INBOX/项目` 等子文件夹继续显示和标色。收件箱仍可作为复制、移动目标。

文件夹默认名称升序，英文与数字开头的名称在前，中文使用简体中文排序规则，数字 2 排在 10 前。列表上方可切换名称降序或邮件数量降序，选择自动保存。查找框匹配名称与完整路径，不改变正在查看的邮件范围。文件夹右侧“⋯”可选择 24 种常用色、自定义色或恢复默认；颜色保存在本机，随备份保留，不修改服务器文件夹。

窗口宽度达到 760px 时，主区域显示邮件列表与阅读区两栏；两栏之间可拖动调宽，支持方向键、Home/End 和双击恢复默认，列宽保存到本机。不足 760px 时，邮件列表与正文切换显示。文件夹在所有宽度下都使用浮层，支持 Escape、遮罩关闭及键盘焦点回归。HTML 正文按实际内容高度展开，长邮件随阅读区统一滚动，阅读工具栏固定在顶部。邮件行悬停或键盘聚焦后显示已读切换与归档快捷操作，阅读工具栏的“更多”收纳导出、显示模式、邮件头和标记操作。

邮件标题旁的彩色位置按钮显示同一账号内、相同 Message-ID 的实际已缓存副本位置；点击可打开该文件夹内的副本。没有 Message-ID 时仅显示当前实例，不按主题猜测。标题旁的文件夹加号打开整理弹窗，可查找目标并选择“复制，保留原邮件”或“移动，离开原位置”。邮件列表右上角按相同位置关联显示非 INBOX 文件夹的颜色，多个文件夹使用分色角标，悬停可查看账号与全部完整路径；无需先打开邮件。

正文中的 HTTP/HTTPS 网页链接可直接点击，目标页面独立打开，邮件阅读页保留；纯文本网页地址同样可点击。“邮件中的链接”折叠列表已移除。HTML 正文仍使用隔离容器，不允许邮件脚本、表单或本地文件地址执行；默认外部图片策略保持独立。

阅读区的“邮件往来”默认折叠，点击展开；本次阅读期间后台刷新保留展开状态，切换邮件重新折叠。它显示同一账号内已缓存的原信、回复和已发送回复。分组依据完整回复引用链，并忽略主题前的 `Re:`、`回复：` 等回复前缀；只有标题相同不会合并，实质更换主题会另起一组。同一 Message-ID 存在于多个文件夹时只算一封，文件夹位置仍由标题旁的色标表示。至少两封不同邮件才显示往来列表，最新邮件在前，并高亮“当前邮件”；长往来可加载更早邮件。转发作为新的邮件往来起点。

在“设置 → 日历与待办”选择日历显示时区、新建事件默认时区、默认视图和每周起始日。两个时区初始均为 `Asia/Hong_Kong`，每周从星期一开始。切换显示时区只转换时间显示，已有事件保留原时区和实际时间，全天事件保留原日期；事件编辑窗口也可单独选择时区。日历侧栏“日历偏好”可直达设置。

在“设置 → 邮箱账号”选择默认发件账号、全局自动同步间隔（1–60 分钟，初始为 2 分钟）；每个账号可继承全局间隔、独立设置间隔或暂停自动同步。暂停后仍可手动同步、阅读和发信。在“设置 → 邮件与阅读”设置自动已读及延迟（默认立即已读），也可开启“默认加载外部图片（HTTPS）”，初始关闭；每封邮件的图片按钮可单独覆盖当前选择，换一封邮件后重新遵循默认值。CID 内嵌图片独立显示。默认账号用于新建邮件；账号不可用时自动选择其他已启用邮箱，回复沿用来源账号。每个邮箱的“配置 → 默认签名”可选择已创建的签名，新建、回复和转发时插入，已保存草稿保留原内容。修改后点击本分类的“保存设置”；偏好保存在本机并包含在备份中。

邮件页面两条竖向分隔线支持鼠标拖动：分别调整文件夹栏和邮件列表的宽度，正文占用剩余空间。列宽保存到本机，刷新和 DSH 重启后保留。双击分隔线恢复对应栏的默认宽度；聚焦分隔线后可用左右方向键微调，Shift 加速，Home/End 调整到可用范围的最小/最大值。窄窗口自动切换文件夹抽屉或单栏阅读，再次放大时恢复保存的宽度。

“设置 → 通知 → 启用 Windows 系统通知”可开启或关闭系统提醒，默认开启；点击“测试系统通知”可检查本机弹窗和声音。新邮件、日历、待办和跟进提醒由 Host 直接提交给 Windows 通知中心，默认使用系统提示音，可在插件中关闭声音，并遵循 Windows 的通知、音量和免打扰设置。邮件页面隐藏或 DSH 最小化后仍可提醒；首次同步历史邮件、已发送副本及 UIDVALIDITY 变化后的缓存重建不会触发新邮件通知。系统通知失败时保留应用内提醒；重新打开界面不重放历史提醒。

普通提醒不调用模型。所有同步、定时发送和提醒仅在 DSH Host 运行期间执行。

阅读页的工具栏、主题和发收件人信息在正文滚动时保持置顶，小屏可在头部内滚动完整信息。空名称或只有引号的名称显示完整邮箱。常见的 `>`、`On … wrote:`、中文回复标记及 HTML blockquote/Gmail 引用显示为独立的“引用往来”区域；不确定的格式保留在原正文中，不删除内容。

平铺在 HTML 段落或换行中的“横线 + 日期 + 邮箱”同样可识别。每封历史引用有独立的“引用邮件”编号、淡紫标题栏、粗边框和背景；日期与邮箱保留在卡片头部，引用正文及链接保持原顺序。旧回复草稿也支持这种格式的正文与引用分离。

写信页采用紧凑头部，抄送/密送按需展开；发送、附件和图片按钮固定在底栏。格式栏使用图标与悬停名称，支持字体、字号、文字颜色和背景高亮、粗体/斜体/下划线/删除线、两类列表、撤销/重做及清除格式；模板和签名位于图标菜单中。格式随草稿保存并写入邮件 HTML，切换纯文本会移除本次正文格式。写信页将本次输入与原信引用分开，引用默认折叠并随信发送。AI 回复直接打开同一写信页；紫色 AI 按钮展开紧凑操作条，填写要求后直接生成到现有主题与正文，在正文中继续编辑，再预览确认发送。生成期间编辑过草稿时，旧结果不能覆盖新输入。润色和翻译草稿只改本次撰写部分，保留引用。

快捷翻译、总结、AI 回复、写信和润色共用邮箱侧栏的原生 Agent 会话、模型、邮件工具与历史。任务在启动时固定邮件与已保存草稿的完整上下文；切换邮件不会把运行中的任务改成另一封邮件。翻译和摘要在原邮件正文位置切换查看；写信结果直接写入当前草稿，并可点击“在助手中查看”继续追问。同一会话忙碌时不另起快捷任务，取消不会撤销已经完成的业务操作。所有模型工具调用保持 Agent 权限，发送和永久操作继续由真人确认。

设置中心包含邮箱账号、外观与动效、邮件与阅读、写信/签名/模板、通知、日历与待办、AI 助手、存储与备份、诊断与关于九个分类，支持搜索、局部保存及按分类恢复默认。新草稿可以默认使用纯文本并展开抄送/密送；已有草稿保留自己的格式。通知可按邮件、日历和待办分类开关，配置声音与免打扰时段；静默期间仍保留应用内提醒。存储管理仅清理明确登记的临时导出，先展示清单后确认；诊断导出不包含正文、主题、地址、凭据或完整本地路径。

在写信页固定底栏打开“发送选项”，通过“发送方式”选择立即发送或定时发送，选择计划日期和发送时区；完整计划随草稿保存。夏令时跳过或重复时段须改选无歧义时间。定时任务由本机 DSH Host 执行，必须保持运行和联网；应用退出、休眠错过时间后要求重新预览确认，失败或结果未知不会自动重发。确认后在草稿与发件箱查看排队时间，投递开始前可以取消；开始后无法撤回。

通知面板使用简短的未读、已读、正在发送、已发送和失败状态。成功打开邮件或标为已读后，会自动清除对应的新邮件提醒；同批其他未打开的邮件继续保留，不需要再点“已知晓”。打开邮件时清除提醒不改变已设置的自动已读延迟。任务细节与操作记录默认折叠，发送等需要真人确认的操作继续保留确认入口。

SMTP 明确接受的邮件不再留在草稿箱；失败和发送结果未知的邮件继续保留。发送记录保存在“通知与任务 → 发送记录与回执”，可核查回执、部分收件人拒绝及已发送副本保存失败，不提供再次发送原邮件的入口。SMTP 接受不等于送达或已读。

## 邮件内快捷操作

点击阅读页的发件人、收件人、抄送姓名或写信页已解析的地址，可直接添加或编辑联系人、修改姓名和分组、复制邮箱、给此人写信，或查看双方往来。联系人页的“往来邮件”使用同一完整地址精确查询，不限于对方发来的邮件。

首次升级会分批整理已缓存的有效已发送文件夹和本机成功发送记录，之后随同步、成功发送继续收集 To/Cc/已知 Bcc。排除自己的全部账号地址，已有联系人按邮箱去重；自动收集只补缺失信息，手工姓名和分组保持，删除的联系人不会自动恢复。部分收件人被 SMTP 拒绝时只收集已接受的地址；SMTP 接受仍不表示送达或已读。

写信底栏的 **AI 写信** 展开正文上方的紧凑操作条，可按要求撰写、润色或翻译草稿，结果直接写入现有主题和正文编辑器，无需额外应用。生成期间仍可编辑；草稿发生变化时保留新编辑，并提示重新生成或复制生成内容。收件地址、附件、引用和发送选项保留。阅读页的 **翻译本邮件** 与 **总结邮件** 在当前正文位置显示结果，通过固定邮件头下的“原文／译文／摘要”切换；**AI 回复** 进入同一写信页并直接生成回复正文。所有发送继续经过预览确认。

新信默认简体中文，润色保留草稿语言，回复跟随原信语言；可选择英语、日语或自定义语言。邮件内 AI 在独立邮件主面板使用 DSH 默认模型，在会话侧栏使用当前会话模型，不需要经聊天框中转。打开邮箱 AI 侧栏后，快捷 AI 跟随该助手会话选择。回复包含当前邮件的完整 HTML/纯文本引用；仅提供当前主题、正文及必要邮件头，不自动读取往来中未被引用的其他邮件或附件；结果按纯文本显示。内置请求限 96 KiB 输入、8192 输出 token、120 秒，源正文截断、输出截断、模型配置错误或取消均明确反馈。翻译和摘要只在当前界面保留；写信结果写入正文后随草稿保存。

## 邮箱助手

点击右上方 **AI 助手** 即可边读信边对话。侧栏使用独立邮箱助手会话，保留聊天记录，支持选择模型与模型提供的思考档位、停止生成、查看工具结果；关闭再打开或刷新页面后继续同一会话。每轮开始时读取当前邮件完整正文及引用和已保存草稿，侧栏显示当前主题。草稿自动保存完成后再向助手提出修改要求。附件默认只提供元数据，需要时由工具按任务读取。

可在侧栏或专用预设中说：

> 找出上个月客户发来的报价邮件，返回来源。
>
> 把这几封邮件加星，复制到“项目 A”文件夹。
>
> 从这封邮件提取截止时间，添加待办并保留依据。
>
> 准备回复：我会在周五前交付。

搜索先返回摘要与索引覆盖情况，正文按需提供给当前 DSH 模型。不自动上传完整邮箱或创建云端向量索引。邮件文字和附件是待处理资料，不能扩大工具权限。

邮箱助手操作会自动打开当前会话右侧工作台：搜索和筛选展示结果列表，读信定位正文，写信和回复打开可编辑草稿，待办与联系人定位并高亮记录，日历跳到事件日期并显示对应日历，规则显示命中预览或已保存规则，附件打开预览，导出触发浏览器下载。已完成待办也会展示；已有编辑或弹窗会暂缓切换，关闭后再显示助手结果。内部分析可使用 `display:false` 避免频繁切页，最终操作保持默认展示。

发送、对外日历邀请/回复和永久删除通过服务器保存的具体预览确认；修改草稿后旧预览失效。Agent 没有确认入口，`confirmed: true` 无效。规则保存后停用，用户在界面启用后才自动执行。

## 发送、回执与故障恢复

- 立即发送确认后保留 **10 秒发件箱缓冲**。开始 SMTP 投递后不提供撤回承诺。
- SMTP 接受、明确拒绝、结果未知分开保存。投递末尾断线不自动重发；已发送副本写入失败也不重发原邮件。
- Host 重启或休眠错过发送时间后，需要重新确认。修改发件配置会使已批准的排队邮件重新待确认。
- 本机方案提供 **请求和接收标准已读回执（MDN）**，不提供被动图片追踪。没有回执时状态为**未知**。回执是收件端报告，并非对真实阅读的证明。
- 跨账号移动先复制并核实 APPENDUID，确认后才处理源邮件。服务器缺少安全单封清除能力时停止，不执行整个文件夹 EXPUNGE。
- 附件按需下载。单封原件/附件下载上限 50 MiB；单段正文缓存上限 2 MiB，截断会提示。导入单次上限 100 MiB，恢复数据上限 1 GiB。

远程图片默认阻止，HTML 经清理后在禁止脚本和表单的 iframe 显示；用户可单独允许当前邮件的 HTTPS 图片。附件保存检查路径，不自动执行附件或访问邮件外链。

## 数据与更新

插件数据位于 `resolveDshHome()/dsh-mail/<profile>/`，包含 SQLite、附件、原件缓存和导出文件，与仓库代码分离。默认桌面 profile 是 `desktop`。

更新前先在“设置 → 备份”导出，并检查下载文件。当前 DSH 的第三方插件界面要求卸载后重新安装新版；数据目录独立，重新安装同一 GitHub 来源后会继续使用原数据。**不要手动删除数据目录。** 更新完成核对插件版本、日历、待办和邮件缓存，并重启复验。

数据库升级前创建一致性快照，迁移在事务中进行。恢复备份只允许在空邮箱数据环境中执行，避免覆盖已有邮件；恢复的远程账号和规则默认停用。回退代码时，若数据库格式更新，也需要恢复匹配版本数据，不能只回退 JavaScript 文件。

## 开发

```powershell
npm ci --ignore-scripts --legacy-peer-deps
npm test
npm run build
npm run check
npm run benchmark
```

`npm test` 包含真实本机 IMAP/SMTP 测试服务器，需允许回环网络。Windows 额外验证 DPAPI。`benchmark` 生成 3 个账号、10 万封合成邮件并将结果写入 `.cache/benchmark.json`，不使用真实邮件。

界面验收脚本使用仓库 `.cache/dsh-home` 中的隔离 DSH Host。首次初始化基础数据运行 `node scripts/seed-fixtures.mjs`，再运行 `node scripts/seed-navigation-fixtures.mjs` 添加导航合成数据。启动该隔离 Host 后，用 `node scripts/verify-ui.mjs "<隔离 Host 的完整回环 URL>"` 执行 Edge 截图与交互验收。脚本覆盖左侧入口、对话重复入口排除、主面板、排序、查找、颜色、已发送、回复预览及明暗主题；截图和结果写入 `.cache/`。此流程不会确认发送邮件。

`node scripts/verify-layout-ui.mjs "<隔离 Host 的完整回环 URL>"` 验证分隔条拖动、键盘操作、复位、重载持久化及明暗主题和窄屏截图；加 `--notify` 会通过真实 Host 提交一条合成 Windows 测试通知。设置 `DSH_RUNTIME_MODULES` 为目标运行时的 `node_modules` 绝对路径后运行 `npm test`，可同时验证原生插件和 Agent 对实际 DSH 包的加载。

`node scripts/seed-conversation-fixtures.mjs` 添加本机合成往来与链接样本；`node scripts/verify-conversations-ui.mjs "<隔离 Host 的完整回环 URL>"` 在真实页面验证正文点击、独立目标页、往来去重与分页及明暗主题截图。目标网址由测试浏览器本机拦截，不访问真实邮件外链。

在实际安装 DSH 的 Windows 上设置 `DSH_TEST_DESKTOP_IDENTITY=1` 后运行 `npm test`，会核对通知发送身份是否出现在 Windows 已注册的 DSH 应用中。Windows 通知接口返回成功或通知历史可读回，均不能代替横幅与声音的实际验收。


Agent 联动的隔离界面验收：运行 `node scripts/prepare-agent-ui.mjs "<DSH rc.3 node_modules 目录>"`，把输出的测试插件 insert 加到 **`.cache/dsh-home/profiles/web/cordis.patch.yml`** 后启动该隔离 Host，再运行 `node scripts/verify-agent-ui.mjs "<完整回环 URL>"`。测试插件强制核对仓库隔离 `DSH_HOME`，通过原始 `dsh/agent.mjs` 和该 SDK 的 `defineTool` 执行真实工具回调，连接同一 Host 内的邮件服务；测试后停止 Host 并移除该 insert。此验收不调用真实模型、不确认发送，截图和下载文件仅存 `.cache/`。

前端使用 DSH 提供的 React；IMAP/SMTP/MIME 使用 ImapFlow、Nodemailer 和 MailParser，日历使用 FullCalendar Standard、ICAL.js 和打包时区数据，富文本使用 Tiptap 开源组件。运行与依赖说明见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

本项目代码为 MIT，依赖保留各自许可。参考项目包括 [Mailspring](https://github.com/Foundry376/Mailspring)、[Inbox Zero](https://github.com/elie222/inbox-zero) 和 [dsh-mail-connector](https://github.com/aizzaua/dsh-mail-connector)，本项目未移植这些项目的应用代码。

`node scripts/prepare-mail-actions-ui.mjs "<DSH rc.5 node_modules 目录>"` 准备仓库隔离目录中的合成联系人、邮件和本机 LLM 适配器。只对 `.cache/dsh-home` 启动 Host 时添加 `--patch .cache/mail-actions.patch.yml`，再运行 `node scripts/verify-mail-actions-ui.mjs "<完整回环 URL>"`。适配器不访问外部模型；验收覆盖取消、错误、草稿冲突、应用、联系人操作、主面板/会话侧栏及明暗主题/窄屏截图，测试后停止 Host。不得给日常 profile 添加此测试 overlay。

`node scripts/verify-mail-experience-ui.mjs` 在独立缓存目录启动真实 App 与 MailService 的合成验收环境，覆盖固定头部、地址显示、引用分区、AI 结果编辑/取消/重试/冲突、定时计划、排队取消、草稿清理、明暗主题与窄屏。模型与传输均为替身，断言 SMTP 调用为零；结果和截图写入 `.cache/`。此脚本不启动用户日常 Host。
